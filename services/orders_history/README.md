# orders-history

Журнал саги: по одной строке на каждое событие. Ничего не решает и
никуда не отвечает событиями — только читает и записывает.

## Роль в саге

Подписан на **оба** топика — `orders.events.v1` и
`notifications.events.v1`, — чтобы в журнале лежала вся цепочка, а не
половина. Успешная сага оставляет четыре записи с общим `saga_id`.

## Процессы

| Команда | Что делает |
|---|---|
| `uvicorn orders_history.main:app` | HTTP API |
| `python -m orders_history.consumer` | пишет события в журнал |

Идемпотентность по `event_id`: повторная доставка не создаёт вторую
строку.

## API

| Метод | Путь | |
|---|---|---|
| GET | `/api/v1/orders_history/history` | журнал с фильтрами `order_id`, `user_id`, `event_type` |

Плюс `/health`, `/ready` и `/metrics`.
